# Snapbuild — тестовое задание

Статически генерируемый продуктовый лендинг на Nuxt 4. Существующая структура Снэпбилда дополнена пятью новыми секциями, интерактивными сценариями и доступной демоформой.

## 1. Опубликованный результат

Публичная версия: https://igor-popryadukhin.github.io/snapbuild-test-task/

Страница не требует авторизации, работает под base path `/snapbuild-test-task/` и публикуется через GitHub Actions.

## 2. Локальный запуск

Требуется Node.js 22+ и npm 11+.

```bash
npm ci
npm run dev
```

По умолчанию Nuxt покажет локальный адрес в терминале.

## 3. Проверки и production-сборка

```bash
npm run lint
npm run typecheck
npm run test
NUXT_APP_BASE_URL=/snapbuild-test-task/ npm run generate
npm run preview
```

Тесты покрывают утилиты валидации, drag-scroll, сценарии вкладок, карусель и интерактивные состояния секций. Результат генерации находится в `.output/public` и не коммитится.

## 4. Стек

- Nuxt 4, Vue 3, Composition API и `<script setup>`;
- TypeScript со строгими контрактами;
- SCSS, локальные дизайн-токены и TT Commons Pro;
- Vitest, Nuxt Test Utils и ESLint;
- статическая генерация и GitHub Pages.

## 5. Пять новых секций

1. «Сценарии использования» — интерактивные маршруты для маркетинга, дизайна, продаж и продукта.
2. «Как проходит внедрение» — пять последовательных этапов с результатом каждого шага.
3. «Измеримый эффект» — иллюстративные показатели и сравнение процесса до/после.
4. «Истории клиентов» — три явно обозначенных демонстрационных сценария с клавиатурным управлением.
5. «Запросить демо» — клиентская форма с ошибками, loading, успешным состоянием и сбросом без сетевой отправки данных.

## 6. Анализ визуального языка

Исследование исходного лендинга зафиксировано в [`docs/design-audit.md`](docs/design-audit.md). В реализации сохранены крупная акцидентная типографика, монохромная база, яркие акценты, скруглённые поверхности, плотная модульная сетка и спокойные переходы. Новые блоки используют существующие шрифты, ритм и компоненты вместо отдельного UI-kit.

## 7. Что реализовано

Лендинг образует последовательную историю: знакомство с продуктом → форматы и ролевые сценарии → внедрение и эффект → сравнение, безопасность и roadmap → демонстрационные истории → запрос демо → финальный CTA → FAQ. Интерактивные элементы доступны с клавиатуры, учитывается `prefers-reduced-motion`, изображения имеют зарезервированные размеры, а горизонтальные интерфейсы остаются внутри собственных scroll-контейнеров.

Для контрольных ширин 375, 768, 1280 и 1440 px реализованы отдельные адаптивные правила. Автоматические проверки покрывают навигационные якоря, клавиатурные вкладки, форму, FAQ и состояние карусели; production-сборка дополнительно проверяется в браузере без ошибок приложения в консоли.

## 8. Ограничения

- Истории, компании и показатели эффекта — демонстрационные продуктовые сценарии, а не подтверждённые отзывы или аналитика клиентов.
- Форма намеренно не отправляет и не сохраняет персональные данные; backend и интеграция с CRM не входят в решение.
- Контент воспроизводит исследованный снимок исходного сайта и не синхронизируется с ним автоматически.
- Численные показатели Lighthouse не зафиксированы: они зависят от среды запуска и требуют отдельного воспроизводимого отчёта.

## 9. Возможные улучшения

- подключить реальный защищённый endpoint формы и серверную валидацию;
- заменить демонстрационные истории проверенными кейсами после согласования с клиентами;
- добавить визуальные regression-тесты для контрольных viewport;
- автоматизировать Lighthouse budget в CI после фиксации целевых метрик.

## 10. Использование AI

ChatGPT Codex использовался для анализа требований и репозитория, декомпозиции issues, подготовки компонентов, тестов и проверок. Решения сверялись с кодом, acceptance criteria и наблюдаемым поведением; итоговые lint, typecheck, unit-тесты, генерация и browser-проверки запускались на реальном проекте.
